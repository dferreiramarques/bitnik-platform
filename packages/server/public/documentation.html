Documentação

O sistema de design da Bitnik tem três camadas: o design system (bitnikgames-design-system, com versão fixa), a marca de cada deploy (moldura, editável na consola) e o jogo (a mesa, definida no skin.json de cada pacote). Esta página mostra os tokens e componentes da primeira camada, como afinar as outras duas, e os padrões de UI que já se repetem entre os jogos migrados — para o próximo jogo não os reinventar.

Decisões completas: docs/DECISOES.md — ADR-006 (UI de um jogo vive no pacote), ADR-008 (aparência em camadas) e ADR-014 (mesa em ecrã inteiro, painéis de vidro).

Tipografia

Duas letras: uma de exibição para títulos, uma de texto para o resto. Os jogos com UI própria têm os mesmos dois papéis (--game-font-display / --game-font-body), por vezes com outra letra (o Catania usa uma serifada, por exemplo).

Inter — texto corrido. Serve para parágrafos, formulários e qualquer coisa que se leia em linha, dos lobbies ao registo do jogo.

--font-body: "Inter", system-ui, -apple-system, "Segoe UI", sans-serif;

Customização

Três camadas, dois níveis de afinação (ADR-008). Nenhum jogo com UI própria escreve uma cor fixa no código — só tokens, para as duas vias funcionarem.

Design systemQuem define: BitnikOnde vive: repo próprio, versão fixa (@v1.0.0)
Marca (moldura)Quem define: o publisherOnde vive: config do deploy, editável na consola
Jogo (mesa)Quem define: Bitnik por omissão; o publisher pode sobreporOnde vive: ui/skin.json do pacote + afinações na consola

Aparência (afinar tokens)

Na consola, cada jogo mostra os seus tokens com pré-visualização ao vivo sobre o cenário do tutorial; as afinações guardam-se no storage do deploy e chegam a quem está ligado sem recarregar. Aviso automático se o contraste ficar abaixo de AA.

Design à medida (tema completo)

Para ir além dos tokens: um tema com CSS e assets próprios (arte do tabuleiro, cartas, texturas, fontes) em ui/themes/<nome>/. O CSS do tema fica limitado à área da mesa — nunca esconde avisos nem controlos da plataforma. Escolhe-se um tema por deploy; os tokens continuam afináveis por cima.

skin.json de um jogo

Cada token tem um valor por omissão, um tipo (para o editor validar) e uma etiqueta bilingue. A mesa lê sempre pelo nome do token — nunca um valor fixo.

{
  "--table-bg": {
    "value": "radial-gradient(ellipse at 50% 40%, #3f6b52 0%, #1f3328 100%)",
    "type": "background",
    "label": { "pt": "Mesa (fundo)", "en": "Table (background)" }
  },
  "--game-accent": {
    "value": "#b8461f",
    "type": "color",
    "label": { "pt": "Destaque", "en": "Accent" }
  }
}

Padrões da mesa

A mesa ocupa o ecrã inteiro (ADR-014); tudo o resto é um painel flutuante por cima, numa de duas famílias: vidro (fundo, para conteúdo que se lê melhor com contraste próprio) ou flutuante sem fundo (só sombra no texto, para não tapar o tabuleiro).

Painel de vidro

Fundo semitransparente + desfoque + contorno subtil. Usado nos cartões de jogador, na barra de ações e na minha área. Nunca cor fixa — sempre estes três tokens.

Controlo preso ao canto

Zoom, pan e outros controlos flutuantes ficam sempre presos ao canto inferior direito da mesa (não do tabuleiro) — position: fixed funciona porque a mesa tem container-type: size, que a torna o "containing block" do fixed. Assim nunca saltam quando o resto do layout muda de altura. A barra de ações reserva-lhes espaço (margin-right) para nunca ficarem sobrepostos.

Barra de ações
+−⤢
.zoombar { position: fixed; right: max(24px, env(safe-area-inset-right, 0px)); bottom: calc(env(safe-area-inset-bottom, 0px) + 12px); }
.bar { margin-right: 328px; } /* liberta o canto sem encolher o resto */

Modal de regras

O botão "?" durante o jogo abre uma modal com as regras, sem sair da mesa (ao contrário do tutorial). O jogo só declara rules: { pt: [...], en: [...] } no contrato — o resto (botão, modal, tradução) é da plataforma. Experimenta:

Fundo do lobby e miniatura

No lobby, o fundo é sempre o --table-bg do próprio jogo (ADR-008: defaults do skin.json, tema e afinações da consola — a mesma camada que pinta a mesa em jogo), escurecido e com sombra no texto por cima. Não há campo nenhum para isto: muda o --table-bg (na consola ou no skin.json) e o lobby segue sozinho.

A miniatura na página da marca é outra coisa — uma imagem à parte (campo thumbnail do contrato, ou a mesma afinação na consola), porque o fundo da mesa raramente dá uma boa miniatura. Sem thumbnail, fica uma cor lisa.

Catania
thumbnail: './ui/thumbnail.svg', // no contrato do jogo — só a miniatura

/* fundo do lobby, app.css — sem campo, automático para todos os jogos */
